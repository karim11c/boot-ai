## Historical-test results

The original one-year EURUSDm M15 baseline started at $10,000 and ended at $5,125.09 (net -$4,874.91, about -48.75%). It had 2,170 trades, 40.23% winners, profit factor 0.71, expected payoff -$2.25 per trade, and maximal balance drawdown $5,023.92 (50.08%). Gross profit was $12,228.45 versus gross loss $17,103.36.

A second one-year run of the separate research build (including the Chapter 9, 15, 17, and 19 changes plus the Chapter 3/5 breakout-test detector) ended at $4,623.96 (net -$5,376.04). It had 2,139 trades, 38.94% winners, profit factor 0.67, expected payoff -$2.51 per trade, and maximal balance drawdown $5,498.50 (54.98%). This is worse than the original baseline and shows the added heuristics did not improve this historical result. Both tests used zero-latency ideal execution and no commission, so the losses are not explained by conservative cost assumptions. The second run finished in 38 seconds over 11,313,866 ticks and 22,375 bars. Neither result validates the full book method.

The latest source change adds automatic deletion of managed, unfilled pending entries when their attached protective invalidation is reached, deletes managed pending entries when execution is disabled, locks each order's scalp/intraday/swing horizon at placement and carries it to the position on fill, optionally trails beyond the most recent confirmed swing pivot, applies the Chapter 26 countertrend/tight-range gates, and sizes optional Chapter 28 limit orders at a configurable reduced-risk multiplier. It compiled with 0 errors and 0 warnings and was copied to MT5 under the separate research filename `BootAI_V2_Research_Ch26Ch28_20261126.ex5`. A matching tester-only configuration file is prepared, but the launch attempt did not create or update a MetaTester log/report, and the UI state capture returned Codex instead of MT5; therefore no backtest has been run on this change. The order-hygiene, horizon-lock, trail, and new entry gates are unvalidated until the same historical run and dedicated behavior scenarios pass.

## Completion gates

For each chapter, document a concise rule specification, source page references, implementation status, positive and negative chart examples, and an acceptance check. Do not enable execution for a rule while its context, invalidation, entry, stop, and exit are ambiguous. Preserve analysis-only defaults and test only in Strategy Tester until the gates pass.
